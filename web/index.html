Security Scans

Target URL

The base URL of the application to scan (e.g., http://localhost:8000 or https://api.example.com). All scan types use this as the starting point.

Scan Type

Choose the scanning strategy:

  • Baseline (passive) — Passive checks only: security headers, CSP, cookie flags, information disclosure, SSL/TLS configuration. No active probing.
  • API (OpenAPI) — Parses an OpenAPI spec and runs parameter fuzzing, auth validation, and schema compliance tests against each endpoint.
  • Full (active) — Active crawling + injection probes (SQLi, XSS, path traversal, command injection) plus passive checks. Use only on targets you own.

OpenAPI URL (API scan only)

URL to the OpenAPI/Swagger specification (YAML or JSON). The scanner will fetch this and test each defined operation.

Ownership Confirmation

Required checkbox confirming you have permission to test the target. Prevents unauthorized scanning.

Auth Header

Header name used for authentication (default: Authorization). Used for all authenticated requests in API and Full scans.

User A Token

Authentication token for the primary test user. Required for authenticated scans and BOLA (Broken Object Level Authorization) testing.

User B Token (BOLA only)

Second user's token. Used to probe for BOLA/IDOR by attempting to access User A's resources with User B's credentials.

BOLA Probe URLs

One URL per line containing object identifiers (e.g., /api/users/123/profile, /api/orders/456). The scanner attempts to access each with both User A and User B tokens to detect authorization flaws.

Load Tests

Target URL

The exact endpoint to load test (e.g., http://localhost:8000/api/health). Supports query parameters.

Method

HTTP method for the request: GET, HEAD, OPTIONS, POST, PUT, PATCH, DELETE.

Duration (s)

How long to run the test in seconds (1–600). The test generates requests at the target RPS for this duration, then stops. In-flight requests are cancelled at the deadline.

Requests / Second

Target request rate (1–5000). The producer spaces requests evenly (e.g., 50 RPS = one request every 20 ms). Actual achieved RPS may be lower if the target is slow (backpressure).

Concurrency

Number of simultaneous workers (1–500). Each worker processes one request at a time. Higher concurrency allows more in-flight requests when latency is high, but consumes more connections.

Headers (optional)

Request headers in either format:

  • Name: Value — one per line (e.g., Authorization: Bearer token)
  • JSON object — paste a full JSON object (e.g., {"X-API-Key": "abc", "Content-Type": "application/json"})

Request Body (optional)

Raw body for POST/PUT/PATCH requests. Sent as-is for every request.

Ownership Confirmation

Required checkbox confirming you have permission to load test the target.
